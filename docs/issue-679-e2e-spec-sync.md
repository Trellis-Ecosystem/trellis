# Issue #679 — E2E Spec Targets Form Fields and Values That No Longer Exist in the UI

**Issue:** [#679](https://github.com/Trellis-Ecosystem/trellis/issues/679)  
**Branch:** `fix/e2e-spec-sync-current-ui`  
**Scope:** `frontend/e2e/create-agreement.spec.ts`

---

## Background

`frontend/e2e/create-agreement.spec.ts` describes the create-then-view journey against a local Stellar devnet. The spec was written against an earlier version of the UI and has not been updated to track subsequent changes in the form:

- The agreement ID is now generated by an `AgreementIdGenerator` widget rather than typed into a free-text input labelled `Agreement ID (hex)`.
- The milestone amount input's placeholder changed from `Amount (smallest token unit)` to `100`, and the amount is now entered in human-readable decimal form (the page converts it to stroops via `amountToStroops`).
- Party address `<label>` elements have no `htmlFor` wiring, so `getByLabel('Payee Address')` does not resolve to the input.
- The status page renders payer/payee as truncated `ExplorerLink` components (`GAQAA…WRYE`), but the spec asserts the full 56-character address.
- The spec expects `'1000'` on the status page; `CreateAgreementPage.tsx` (lines 40–58) converts `'1000'` to `10000000000` stroops, and that encoded value is what the status page receives and formats via `MilestoneAmount`.

As a result, `npm run test:e2e` via `tests/e2e/run.sh` cannot complete the journey green.

## Required Changes

### 1. Agreement ID — use the generator widget

The `AgreementIdGenerator` component exposes a **Generate** button. Click it, then capture the generated ID from the display element:

```typescript
await page.getByRole('button', { name: /generate/i }).click()
const agreementId = await page.locator('[data-testid="agreement-id-display"]').innerText()
```

Alternatively, if the generator widget accepts a manual override, fill that input directly. Check the current `AgreementIdGenerator` component API to confirm the approach.

### 2. Payee, resolver, and token address inputs — use `getByPlaceholder` or `data-testid`

The `<label>` elements in the form lack `htmlFor` attributes (the existing issue #680 tracks adding them as part of accessibility work). Until that is fixed, target inputs by their placeholder values, which are stable:

```typescript
await page.getByPlaceholder('G...').nth(0).fill(payeeAddress!)   // Payee Address
await page.getByPlaceholder('G...').nth(1).fill(resolverAddress!) // Dispute Resolver Address
await page.getByPlaceholder('C...').fill(tokenAddress!)           // Token Contract Address
```

Or add `data-testid` attributes to the inputs in `CreateAgreementPage.tsx` as the more robust long-term solution.

### 3. Milestone amount — use the MilestoneBuilder's current placeholder

The milestone amount field is rendered by `MilestoneBuilder`. Find the current placeholder (e.g. `'100'`) and fill with a decimal amount:

```typescript
const milestoneAmount = '10'   // 10 tokens = 100000000 stroops
await page.getByPlaceholder('100').fill(milestoneAmount)
```

The spec variable `milestoneAmount` should hold the **human-readable** value that the user types, not the stroops value that arrives on-chain.

### 4. Status-page assertions — assert via ExplorerLink href, not full address text

`AgreementDetail.tsx` renders payer and payee as `<ExplorerLink type="account" value={address} />`, which produces a truncated visible label (`GAQAA…WRYE`) and an `href` containing the full address. Assert the href rather than the visible text:

```typescript
const payerLink = page.locator(`a[href*="${payerAddress}"]`).first()
await expect(payerLink).toBeVisible()

const payeeLink = page.locator(`a[href*="${payeeAddress}"]`).first()
await expect(payeeLink).toBeVisible()
```

### 5. Milestone amount assertion — assert the formatted value

The milestone amount on the status page is rendered by `MilestoneAmount`, which formats the raw stroops value returned by the contract. Assert on what `MilestoneAmount` actually displays rather than the raw stroops integer:

```typescript
// If MilestoneAmount renders '10' for 100000000 stroops:
await expect(page.getByText('10').first()).toBeVisible()
// Or assert on the data-testid if one exists
```

Confirm the exact rendered string by running the journey manually once and inspecting the DOM.
